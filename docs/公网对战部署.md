# 公网对战部署（Cloudflare Tunnel · 跨国）

> 目标：**不改任何业务代码**，只做部署，让国外的朋友能连上你本机的象棋服务，双方联网下棋。
> 本文记录的是**本机实测**结果（2026-10-03，Windows + Python 3.12 + cloudflared 2026.9.3）。

---

## 0. 一键使用（推荐）

### 0.1 程序里直接开联机（最省事）

```bat
python main.py --serve --tunnel          :: 起服务 + 自动拉起 Cloudflare 隧道，打印公网地址
python main.py --serve --tunnel --open   :: 顺便打开浏览器
```
图形界面（`python main.py`）右上角也有一个绿色「联机对战」按钮：点一下会在后台自动开服务、开隧道，弹出对话框显示公网地址，可一键复制或打开浏览器；关闭程序时会自动收掉隧道。

隧道工具的准备逻辑在 `xiangqi/net/tunnel.py`（与下面的脚本等价）：优先用 `tools/bin/cloudflared`，其次 PATH，都没有就下载（官方直链 → GitHub API 兜底），Windows 上校验 Authenticode 签名必须是 Cloudflare, Inc.；默认先试 QUIC，拿不到地址自动退回 `--protocol http2`。

### 0.2 不用程序、只用脚本


```
双击  tools\serve-public.cmd
```

或在项目根目录执行（本机 PowerShell 执行策略是 Restricted，所以必须带 `-ExecutionPolicy Bypass`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\serve-public.ps1
```

脚本会自动：① 准备并校验 cloudflared → ② 确认/启动本机游戏服务（127.0.0.1:8000）→
③ 建立隧道并打印公网地址 → ④ Ctrl+C 时关闭隧道（若服务是它启动的也一并关闭）。
公网地址同时写入 `tools\public-url.txt`。

只想手动来：

```powershell
python main.py --serve                                  # 终端 A：本机服务（默认 127.0.0.1:8000）
tools\bin\cloudflared.exe tunnel --url http://127.0.0.1:8000 --no-autoupdate   # 终端 B：隧道
```

## 1. 本次实测结果（真实数据）

| 项目 | 结果 |
|---|---|
| 隧道 | Cloudflare Quick Tunnel，本次会话共起过两条：`https://notification-voice-invalid-salon.trycloudflare.com`（手工验证用）与 `https://dame-ampland-cigarette-acc.trycloudflare.com`（一键脚本生成）。**临时地址，重启即变；当前有效地址见 `tools\public-url.txt`** |
| 隧道协议/落地 | QUIC，边缘 **lax07**（洛杉矶）；precheck 全 **PASS**（DNS / UDP 7844 / TCP 443 / Cloudflare API） |
| **外部网络可达性** | 从**本机之外**的网络路径抓取 `https://…trycloudflare.com/` → **HTTP 200**，完整返回中文网页；`/api/health` → **HTTP 200 JSON** ✅ |
| 网页与静态资源（本机经公网往返） | `/` 1469 ms、`/app.js` 1531 ms、`/logic.js` 2296 ms、`/style.css` 1313 ms（含每次新建 TLS 握手，属偏高估计） |
| 建房 / 入座 / 走子 | 2422 ms / 984 ms / 1030 ms、985 ms ✅ |
| **WebSocket** | `HTTP/1.1 101 Switching Protocols`，`Sec-WebSocket-Accept` 校验通过，双方实时收着法 ✅（891 ms 握手） |
| **长轮询** | 空事件挂起 8 s 正常返回 `timeout`；对手走子后 **2.61 s 被唤醒**并带到 `h2e2` ✅ |
| `cid` 幂等 / `base_seq` 过期 | 经公网仍成立：重发 `replayed=true` 且 seq 不变；过期请求 `409 stale` + 快照 ✅ |
| **SSE** | ❌ **被快速隧道整包缓冲**：本机直连首帧 0.02 s，经隧道 45 s 收不到任何字节，直到流结束才整包到达 |

### SSE 结论是怎么得出的（避免误判为本服务的问题）

用一个**最小裸 socket SSE 服务**（标准 `Transfer-Encoding: chunked`、每 0.5 s 发一帧、
无任何业务逻辑）替换 8000 端口的源站，经同一条隧道访问，结果**同样被缓冲**：
客户端 21 s（= 流自然结束）才一次性拿到全部内容。加大到 32 KB 起始填充也无效。
因此这是**快速隧道对普通 HTTP 流式响应体的缓冲行为**，不是本程序的实现缺陷。

对实战的影响很小：浏览器客户端按 **WebSocket → SSE → 长轮询** 顺序降级，而 **WebSocket 正常**，
所以国外朋友打开就是 WebSocket 直连；万一他的网络封了 WS，SSE 会在约 60 秒内自动降级到长轮询
（实测长轮询可用），棋局照下，只是那 60 秒会白等。
你在意 SSE 的话，用下面的「命名隧道 + 自有域名」通常可正常流式转发（未在本机验证，因为需要账号/域名）。

## 2. 三种暴露方式对比

| 方式 | 适用 | 优点 | 代价 |
|---|---|---|---|
| **快速隧道**（本文默认） | 临时和朋友对局、验收 | 免账号、免域名、自动 HTTPS（`https://*.trycloudflare.com`）、WS 可用 | 地址随机且重启即变、无 SLA、**SSE 被缓冲** |
| **命名隧道 + 自有域名** | 长期固定地址 | 地址固定、可挂自有域名、WAF/访问策略、SSE 更可能正常 | 需要 Cloudflare 账号与域名；`cloudflared tunnel login/create/route dns` |
| **局域网直连** | 朋友同网段 | 零依赖、零延迟 | 需要 `--host 0.0.0.0` + 防火墙放行；跨国不可用 |

局域网模式（脚本已支持 `-Lan`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\serve-public.ps1 -Lan
# 等价于：python main.py --serve --host 0.0.0.0 --port 8000
# 并需要（管理员一次）放行防火墙：
#   New-NetFirewallRule -DisplayName "Xiangqi 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
# 本机网卡地址：脚本 -Lan/--lan 会自动检测并打印（Windows: ipconfig；Linux: ip addr）
# 这里不要写死自己的内网 IP，避免把私有网络信息提交到公开仓库
# 朋友访问： http://<你的局域网IP>:8000/
```

> 备用方案：本机 `ssh.exe` 可用，且 `localhost.run` / `serveo.net` 的 22/443 端口可达，
> 理论上可用 `ssh -R 80:localhost:8000 nokey@localhost.run` 做免装工具的反向隧道；
> 但那是第三方中转，请自行评估信任。

## 3. 本机网络环境（作者机器上的两个坑，**不是本项目的依赖**）

> 下面两条只是“作者这台机器”的实际情况记录，方便遇到同类现象时对照排查；
> 在正常网络上直接下载官方直链即可，脚本已经按“直链优先、API 兜底”的顺序处理。

1. **github.com 直连被重置**（作者机器上）：`Invoke-WebRequest` 下载 GitHub Release 会失败
   （TCP 443 可连、TLS 握手被断），而 **`api.github.com` 正常**。
   所以脚本会先试官方直链，失败后再走 API 取资产地址（会 302 到
   `objects.githubusercontent.com`，该主机可达）。注意**未认证的 GitHub API 有速率限制**
   （作者在排查时就遇到过 `API rate limit exceeded`），所以 API 只作兜底；
   实在不行可用 `-CloudflaredUrl <直链>` 手工指定，或按官方页面自行安装。
   手工等价命令：

   ```powershell
   $rel = (Invoke-WebRequest 'https://api.github.com/repos/cloudflare/cloudflared/releases/latest' -Headers @{'User-Agent'='x'} -UseBasicParsing).Content | ConvertFrom-Json
   $a = $rel.assets | ? { $_.name -eq 'cloudflared-windows-amd64.exe' }
   Invoke-WebRequest $a.url -Headers @{'User-Agent'='x';'Accept'='application/octet-stream'} -OutFile tools\bin\cloudflared.exe
   Get-AuthenticodeSignature tools\bin\cloudflared.exe   # 必须 Valid 且签发者含 Cloudflare
   ```

   本机还配置过一个本地代理（`127.0.0.1:7897`，Clash 类客户端的默认混合端口，当前**没有运行**）；
   若把它启动起来，GitHub 直连一般也能通。这类环境细节与项目本身无关，换机器不需要照搬。
2. **QUIC/UDP 与 443 都通**：cloudflared 的 precheck 六项全 PASS，默认用 QUIC；
   如果哪天网络封了 UDP 7844，可改用 `--protocol http2` 回退到 TCP 443。

下载到的 `cloudflared.exe`（52.8 MB，v2026.9.3）签名校验记录：

```

sha256: F096265EC2FCBE9BB6E2D64268DB167CED3FCBB83D894BDB9E2FCDB26F2EA7E2
```

## 4. 公网暴露安全清单（务必读）

* **房间号 + 座位令牌就是全部凭据**。链接泄露 = 别人可以坐进黑方；所以先「创建房间」再发链接，
  别把房间号贴在公开群里。
* 隧道模式只需监听 **127.0.0.1**（脚本默认如此），公网入口只有 Cloudflare 一条；
  **不要**图省事开 `--host 0.0.0.0` 又不设防火墙。
* 只在对局期间开隧道，**结束后 Ctrl+C**（脚本会关闭隧道）。快速隧道地址是临时的，关掉即失效。
* 服务端已有的防护（无需额外配置）：单房间最多 2 个座位（第三人 `room_full`）、
  请求体 ≤ 16 KB、单帧 ≤ 1 MiB、每房间 4096 条事件、同时最多 500 房间、空闲 6 小时回收、
  座位令牌常量时间比较、错误一律返回 JSON。
* 对局数据**只在你本机内存**：重启服务 = 对局结束；服务器不落盘、不收集个人信息。
* HTTPS 由 Cloudflare 提供（浏览器到 Cloudflare 是加密的，Cloudflare 到你本机是隧道内加密）。

## 5. 故障排查

| 现象 | 排查方向 |
|---|---|
| 脚本报“隧道建立失败” | 看 `%TEMP%\xiangqi-tunnel.log`；多为 UDP 7844/TCP 443 被限，试 `--protocol http2`；确认 `api.cloudflare.com` 可达 |
| 拿到地址但打不开 | 用 `Invoke-WebRequest https://<地址>/api/health` 自测；新隧道地址生效有几十秒延迟；确认隧道进程还在（`Get-Process cloudflared`） |
| 网页卡在“正在准备棋盘…” | 一般是房间凭据过期或状态栏显示“未连接”：点「创建房间」重来；看浏览器控制台是否有 `/api/rooms` 报错 |
| 能打开但走子无反应 | 看状态栏传输类型：WebSocket 正常；若显示 SSE 且久无更新，是快速隧道缓冲 SSE —— 等约 60 秒自动降级到长轮询 |
| 一方断网/刷新 | 设计上会自动恢复：`localStorage` 保存房间+令牌，重连带 `since` 补发缺失事件；必要时刷新页面 |
| 端口被占用 | `python main.py --serve --port 9000`（脚本支持 `-Port 9000`） |
| 双击 .cmd 后满屏“不是内部或外部命令” | 批处理里混进了非 ASCII 文本：`cmd.exe` 按 OEM 代码页读取，中文会变成乱码并被当命令执行。现在的 `serve-public.cmd` 是**纯 ASCII**（中文提示由 PowerShell 打印），并有测试守护 |
| .ps1 报“字符串缺少终止符”或中文乱码 | 脚本缺 **UTF-8 BOM**（Windows PowerShell 5.1 会按 ANSI 解码）。`serve-public.ps1` 已带 BOM，同样有测试守护 |
| 控制台中文显示乱码 | 先执行 `chcp 65001`（`.cmd` 里已经自动切了；直接开 PowerShell 手动跑时可自行切换） |

### 5.1 脚本编码约定（已写进测试，防回归）

`tests/test_offline.py::TestDeploymentScripts` 会强制这三条：

| 文件类型 | 硬性要求 | 原因 |
|---|---|---|
| `.cmd` / `.bat` | **纯 ASCII、无 BOM** | `cmd.exe` 用当前 OEM 代码页（中文系统 936）读批处理，UTF-8 中文会被当命令执行 |
| `.ps1` | **必须带 UTF-8 BOM** | Windows PowerShell 5.1 对无 BOM 文件按 ANSI 解码，中文会破坏语法 |
| `.sh` | **LF、无 BOM、带 shebang** | CRLF 会让 bash 报 `\r: command not found`；BOM 会破坏 shebang |

换行符由仓库根目录的 [`.gitattributes`](../.gitattributes) 强制：`*.sh` 一律 LF，
`*.cmd` / `*.bat` / `*.ps1` 一律 CRLF。这样在 Windows 上检出（`core.autocrlf=true`）
也不会把 shell 脚本变成 CRLF——这一点在 Windows CI 上被测试真实抓到过。

所以：给 Windows 用户看的**中文提示只放在 .ps1 里**，`.cmd` 只做“切代码页 + 调 PowerShell + 传参”。

## 6. 验收清单（和国外朋友一起走一遍）

- [ ] 对方能打开公网链接，看到中文棋盘与「创建/加入房间」
- [ ] 你创建房间，对方用房间号或 `?room=XXXXXX` 链接入座，双方各占红黑
- [ ] 双方各走几步，对方实时看到落子（状态栏显示 **WebSocket**）
- [ ] 对方刷新页面：仍是原座位、着法记录与棋局完整
- [ ] 对方断网 30 秒再恢复：棋局自动补齐、轮次正确
- [ ] 一方认输或走到将死：双方看到结果与原因
- [ ] 记录双方各自的操作延迟（跨国正常值：欧洲 150–300 ms，美洲 200–400 ms 往返）
- [ ] 结束：你按 Ctrl+C 关隧道；确认对方再刷新就打不开了
